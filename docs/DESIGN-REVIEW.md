# 全模板設計審查紀錄(2026-07)

對全部 14 個模板做的一次系統性審查。原則:只修「會影響列印成敗或使用安全」的問題,不為改而改。所有修改後,**14 個模板的預設輸出與審查前逐位元一致**(用 `npm run verify` 的三角形數/尺寸比對),確定沒有意外改到既有行為。

## 修了什麼

### 1. 重複程式碼整併(不影響幾何)

`buildStrut`(連接臂)在風扇支架三個模板各複製一份、2D 工具(圓角矩形/橢圓/兔耳/梯形/排版)只存在娃娃椅檔案裡。全部抽到共用的 `src/templates/geo.ts`,之後新模板直接引用,改一處生效三處。

### 2. 極端參數防呆(每一項都加了迴歸測試)

使用者把滑桿拉到極端組合時,原本可能產生「印不出來或印了不能用」的幾何。逐一加了防呆鉗制(clamp):

| 模板 | 問題 | 修法 |
|---|---|---|
| 圓柱/套筒 | 內徑 ≥ 外徑 → 整支被挖空消失 | 內徑自動鉗制,永遠保留 ≥0.4mm 壁厚 |
| 收納盒 | 底板厚度 > 盒高 → 空腔反轉出錯;蓋子卡榫深過內腔 | 底板 ≤ 盒高−1;卡榫深 ≤ 內腔深 |
| L型支架 | 孔位內縮 > 臂長 → 鎖孔跑到零件外面(沒孔) | 孔位自動鉗制在臂內、離邊 ≥1.5mm |
| DIMM 壓桿 | 漏斗口比主體寬 → 夾槽兩壁消失、完全失去保持力;斜切量比握把大 → 握把被切光 | 槽口 ≤ 主體寬−1.2mm 且永不窄於深處寬(避免反向漏斗);斜切 ≤ 握把一半 |
| 風扇支架骨架 | T 型滑槽頸+頭深度 > 軌道厚 → 滑槽打穿頂,腳直接掉出來;頭寬 ≥ 外框寬 → 側壁消失 | 保證滑槽頂保留 ≥1.2mm、側壁 ≥1mm |
| 設備托高架 | 支腳兩軸同時往內拉超過框寬 → 腳與框架完全分離,印出來是一支飄在半空的獨立柱子 | 偵測「兩軸都脫離框帶」時,自動把較近的一軸拉回接觸位置(用 decompose 驗證過極端值下仍為單一實體) |
| 吊飾展示板 | 卡榫寬 > 邊界留白 → 卡榫凸出板角 | 卡榫/凹槽位置自動收進板邊內 |
| 餐桌椅/搖椅 | 尺寸調很小時,裝飾鏤空會把腳架切碎 | 尺寸低於安全門檻時自動略過鏤空(結構優先於造型) |

### 3. 迴歸測試強化

`scripts/verify-templates.ts` 新增「extreme-value guards」區:上表每一項防呆都有一筆極端參數測試,`npm run verify` 一次跑完(預設 14 筆 + 變體 12 筆 + 極端 8 筆)。以後改模板跑一下就知道有沒有弄壞什麼。

## 審查過但不改的(記錄原因)

- **風扇支架(基本/強化版)腳偏移**:不會有托高架的分離問題,因為每支腳都有放射臂跟著,天然保持連接。
- **散熱托盤(M60)**:上一輪已改成裙牆落地免支撐,`restHeight` 已有鉗制,無新問題。
- **壁掛掛勾**:`armStartZ` 已有鉗制;末端球頭在 0°~120° 全範圍驗證過。
- **風扇支架腳(排版列印)**:卡榫尺寸由滑槽參數減去餘裕推導,參數範圍內不會變負。
- **自訂堆疊模式**:使用者本來就有完全自由(包括做出分離件),不加限制是刻意的。
- **效能**:最重的模板(吊飾板 ~4900 三角形)在瀏覽器即時預覽毫無壓力,不需優化。

## 已知限制(非缺陷,設計取捨)

- 圓角一律用斜切或 hull 圓柱逼近,引擎無真正的 3D fillet。
- 搖椅吊桿與頂樑共面,擺動方向是左右而非前後(玩具展示用途可接受,做真前後擺需要立體交叉結構,列印複雜度不成比例)。
- 餐盤固定方式從原品的側邊鉚釘改為插背板孔(3mm FDM 板做不了可靠的微型鉚釘鉸鏈)。

## 後續修正:餐桌椅組裝失敗(2026-07,追加)

**問題**:餐桌椅實際印出來組不起來——榫頭與卡槽在 3D 對位後根本沒對齊,而且造型也不像使用者提供的參考照片。

**根因(重要教訓)**:上一版「驗證」只確認每個零件能算出有效 manifold、能顯示,**完全沒驗證各零件依組裝姿態擺到 3D 空間後榫槽真的對得上**。零件有效 ≠ 組得起來,這兩件事被當成同一件,是這次審查最大的盲點。

**修法**:
1. 餐桌椅整個重新設計,造型貼近參考(圓弧殼背板+兔耳+橢圓握把孔、外撇腳、前方附圍邊餐盤)。
2. 改用「全部插入座板」的榫接系統:背板下榫、腳頂榫、餐盤前緣舌榫全部進座板的槽,榫厚=板厚,槽=榫+餘裕,位置由共用變數推導保證兩邊一致。
3. **新增「組裝預覽」開關**:每個零件都定義了「平放列印姿態」+「組裝姿態(旋轉+平移)」,開關打開就把零件依組裝姿態擺好 union 起來,直接在工具裡看到組好的樣子。這樣使用者(跟我)能在列印前確認榫槽對得上,而不是拿實際列印去試錯。
4. 用組裝預覽渲染實際確認:背板站正、腳撐住座板、餐盤舌榫入槽,全部對位。

**待辦**:搖椅(doll-swing)有同樣的「宣稱能組裝但未經組裝驗證」風險,尚未用同一套方法重驗,需要比照處理。

## 後續修正:餐桌椅改為開放式椅殼(2026-07,追加)

**問題**:上一版餐桌椅是「平板+卡榫」的箱型結構,娃娃根本放不進去坐;使用者提供的參考照片是市售兔耳款——一體成型的「開放式椅殼」,娃娃從上方直接放進去,前方餐盤可拆。

**修法**:`doll-high-chair` 幾何整個重寫成開放式椅殼(three.js 獨立版與 manifold 工具版同步):
1. **椅殼一體**:座面板 + 低側牆(只做後段 62%,前方開放好放娃娃)+ 站立背板(橢圓握把孔 + 兔耳)+ 腰靠楔形,合成單一件。
2. **真插孔**:座板底下四個「中空插孔」(圓環擠出成管),腳架頂面四支插銷插進去——是真的孔配銷,不再是插銷頂平板。孔徑與銷徑由同一組變數推導(銷外徑 = 孔內徑 − 餘裕)。
3. **餐盤可拆**:椅殼前緣兩支朝前插銷,餐盤兩側環扣套上去,拆下來讓娃娃先坐。
4. **預設尺寸對齊娃娃**:座內寬約 84mm(給長10×寬8cm 的娃娃),`seatWidth` 預設 96。
5. **一次印好**:關掉組裝預覽時三件自動排一盤,`layoutParts` 控制在印床寬度內(預設輸出 193×240mm,落在 P2S 256×256 內)。
6. **實機渲染驗證**:用 Playwright 驅動實際網頁,選到此模板、開組裝預覽截圖確認椅殼開口、腳、餐盤、兔耳都對;關預覽確認三件分離不重疊。不再只靠「manifold 有效」就當通過。

**再修正:為了免支撐,拆成七件(2026-07,追加)**:使用者反映一體椅殼是 L 形,平放列印一定有一面懸空、支撐很多。於是把 `doll-high-chair` 再拆細:①背板(兔耳,底部榫頭)平躺印②座面(低側牆、後榫槽、四個插腳「貫穿孔」、前緣餐盤插銷)平放印③④⑤⑥四支獨立圓錐插腳——外撇角度做在腳身彎折上(頂端插銷仍垂直、插進座面的垂直孔),所以每支腳都能直立在腳掌上印、孔全部垂直好印⑦餐盤。七件全部平放或直立、免支撐。榫孔尺寸由同一組變數推導。用 Playwright 實機渲染組裝預覽(背板站正、四腳外撇、餐盤在前)與排版(七件平躺不重疊、218×233mm 落在 256 床內)雙重確認。`legSplay` 滑桿可調椅腳外撇角度。

## 精修 + 組裝零干涉稽核(2026-07,追加)

**精修**:椅腳插銷升級為**鍵型跑道榫**(扁邊防轉、外撇不會歪)+榫孔口**導角**(自動對正、坐到底);座面**微下凹**;背板兔耳加**內耳浮雕**。餐盤改為**兩支立柱+餐盤環扣**由上套下的乾淨接法(可整片拿起讓娃娃先坐)。

**零干涉稽核(重要)**:用「Vol(A)+Vol(B)−Vol(A∪B)」量測各接合件在組裝姿態下的**實體重疊**,揪出兩個肉眼沒看出來的干涉:①側牆撞到背板(318mm³)②餐盤環扣沒對準、支臂撞插銷(1472mm³)。修法:側牆往中間移開背板、餐盤改立柱+環扣並把立柱高度收在餐盤底下。修完三處接合重疊全部歸零(座+腳 4mm³、座+背 0、座+盤 0,4mm³ 是弧面分面誤差非真干涉)。另加「反向工程」測試:把餘裕設 −0.5(把榫故意做大)必須產生干涉(216mm³),藉此證明榫**真的插進**孔裡、不是剛好錯開。這整套檢查已寫進 `npm run verify` 永久把關,以後改動不會再無聲弄壞卡榫。

## 新增:原創迷你家具系列 mini-bed(2026-07)

**動機**:使用者想印周邊拿去賣,原本的兔耳椅殼/道具明確參考吉伊卡哇角色,商用有版權風險。改開一條**完全原創、無角色、北歐簡約風**的家具產品線,第一款是床。

**設計**:七件——床墊平台(兩長邊微凸圍邊)、四支獨立錐形腳(方形鍵榫防轉)、床頭板/床尾板(頂端圓角、三個裝飾圓孔、底部榫頭插進平台槽)。全部平放或直立列印、免支撐。

**零干涉稽核抓到兩個真的錯誤**:
1. **側邊圍板打到床頭/床尾板**:圍板原本沿床鋪全長延伸,跟床頭/床尾板的插榫位置重疊。修法:圍板長度改成動態算「留出板件插榫區的淨空」,不寫死長度。
2. **床尾板插榫位置號錯**(最重要的教訓):床頭板用 `translateY = slotY + t/2`,床尾板誤用了 `slotY - t/2`(以為兩端方向不同要反過來),實測重疊 783mm³。回頭用旋轉公式重新推導才發現:旋轉後的板厚帶永遠是 `[-t,0]`,不管哪一端,對齊槽位的公式都一樣是 `+t/2`,兩端不該用不同公式——**「感覺應該要對稱處理」的直覺是錯的,要重算才知道**。

**另外抓到一個「稽核方法本身」的坑**:第一次量測顯示床頭板/床尾板跟平台都干涉超過 1600mm³,但改了圍板也沒變,一度以為是量測工具本身出包。追查發現:平台的插榫槽原本寫成「只有在 `incHeadboard` 開啟時才挖」,導致單獨量測「平台」時（其他分件全關）用的是**沒挖槽的平台**,跟量測「平台+床頭板一起」時**有挖槽的平台**根本是兩個不同形狀,體積相減自然對不上。改成「只要平台存在就一律挖好所有槽孔,不管其他分件開關」(跟餐椅座板的榫孔做法一致)才修正。**教訓:分件的幾何不該依賴其他分件的開關狀態,否則零干涉稽核會失真。**

修完四處接合(平台+腳、+床頭板、+床尾板、腳榫反向工程)全部通過,已寫進 `npm run verify`。

## 新增:原創迷你家具系列 mini-table / mini-shelf(2026-07)

**動機**:床做完後使用者要求「一起做一做吧」,把同一條無角色、可商用的北歐簡約風產品線補齊桌子跟收納櫃。

**mini-table 設計**:兩件——圓角桌面 + 四支獨立錐形腳(方形鍵榫防轉,插進桌面底部插孔)。直接沿用床的腳榫參數推導方式,第一次零干涉稽核就全過(桌面+腳 overlap≈0、餘裕−0.5 反向工程 overlap=270mm³),沒有另外抓到錯誤。

**mini-shelf 設計**:五件——底板 + 左右側板 + 頂板 + 背板,全部榫接組裝(側板上下各一長榫,插進底板/頂板的長槽;背板底部榫插進底板槽)。開放式層架(無鏈片/門片,前方全開放好拿取),側板頂端圓角+三個圓孔裝飾跟床頭板同一套語言。

**零干涉稽核抓到一個真的錯誤**:
- **`top+sides` 重疊 69.3mm³**:原本共用一個 `cutSlabJoints(slab, faceZ, intoSign)` 泛用函式處理底板跟頂板兩種槽,但 `intoSign=-1`(頂板)那個方向的槽位 Z 偏移公式跟榫頭實際的世界座標範圍有 0.3mm 的不對稱誤差(手算榫頭範圍 vs 槽位範圍兩邊對不齊)。用「重疊體積 ≈ 榫截面積 × 0.3mm 誤差 × 兩側」反推算出來的數字跟稽核回報的 69.3mm³ 精確吻合,確認診斷正確。
- **修法**:拆成兩個各自接受明確 `tenonZMin`/`tenonZMax` 世界座標範圍的函式(`cutSideSockets`、`cutBackSocket`),槽位 Z 範圍兩端都用同一個 `margin=0.3` 對稱處理,不再靠公式裡的符號翻轉去猜。同時清掉一個順手發現的無效切割:頂板原本也被挖了一個背板榫的凹槽,但背板只有底部榫、頂板根本不會跟它接合,那個切割是多餘的。

**視覺驗證額外插曲**:組裝預覽用 Playwright 從斜角看背板三個裝飾孔,一開始看起來像是有鋸齒狀的破面(懷疑是新的干涉錯誤)。改用正上方俯視角重新截圖後確認孔洞乾淨平整——斜角看到的「破面」其實是低面數圓孔在掠射視角下的鏡面反光瑕疵(跟床頭板同樣 28~32 面圓孔在類似角度下同樣的視覺效果),不是真的幾何問題。**教訓**:組裝預覽的截圖要換多個角度看,尤其是接近水平掠射角度時,鏡面反光容易被誤判成破面,正上方或側面直角視角比較能排除這種假警報。

修完 `top+sides` 之後,mini-shelf 四處接合(base+sides、top+sides、base+back、base+top)全部 overlap≈0,側榫反向工程(餘裕−0.5)overlap=189.7mm³,已寫進 `npm run verify`。

**跟 doll-high-chair 的關鍵差異**:這款椅腳插孔的 Y 座標特地抓大一點的安全邊界(`Math.max(12, seatD/2-18)`,比迷你桌的 `seatD/2-10` 多留將近 8mm),直接借用 `dollChairs.ts` 裡已經驗證過的座椅+靠背間距公式——原因是椅子的靠背插槽開在座面後緣,如果後排腳插孔跟靠背插槽的 Y 範圍沒留夠邊界,兩個切割區在座面內部會彼此貼太近甚至重疊,即使不會讓 manifold 報錯,也可能削弱該處結構。這次直接套用既有驗證過的間距公式而不是重新猜一次,零干涉稽核(座+腳、座+靠背、兩處反向工程)第一次就全部通過,沒有另外抓到錯誤。

修完後四款(床/桌/櫃/椅)全部沿用同一套鍵榫+圓孔裝飾語言,可以互相搭配湊成房間組。
